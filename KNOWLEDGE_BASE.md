# Rockets: Master Project Knowledge Base

This document serves as the permanent master reference for the **Rockets** multiplayer space shooter infrastructure, architecture, configuration, domain concepts, decisions, and operational runbooks. It maintains all architectural decisions, resource IDs, security/environment variables, operational procedures, and file locations across sessions and must be updated **before** making code changes (KB-First Pipeline).

## 1. Executive Summary & Architecture Overview

- **Project Goal:** A responsive, web-based, real-time 3D multiplayer space shooter running entirely peer-to-peer using WebRTC with zero registration, zero central server cost, decentralized master failover with keep-alive TTL heartbeats, set in a **Persistent Planetary Exploration & Orbital Dogfighting Arena** featuring a central mega-asteroid encircled by a halo of 32 large stationary asteroids and an orbiting asteroid belt rendered via Three.js MarchingCubes volumetric density fields, complete with a P2P-synchronized Room Configuration Suite (including tunable flight acceleration and momentum shearing dynamics).
- **Core Technology Stack:**
  - **Frontend / Rendering:** Three.js (WebGL 3D graphics, procedural MarchingCubes volumetric density fields, high-performance GPU `THREE.InstancedMesh` quad billboarding particle & explosion systems with zero heap allocation, low-profile cockpit interior).
  - **Networking / P2P Mesh:** `@trystero-p2p/nostr` (serverless WebRTC signaling using open decentralized Nostr relays).
  - **Build Tooling:** Vite (fast ESM bundler, production minification, automated build-time service worker cache ID injection, hidden sourcemaps).
  - **Hosting:** GitHub Pages via `gh-pages` branch deployment (`npm run deploy`).
- **Deployment & Hosting Model:** Static Progressive Web App (PWA) hosted on GitHub Pages (`https://eitamaath-design.github.io/rockets/`).

## 2. Core Domain Concepts & Feature Specifications

### Domain Concepts & Invariants

- **Peer-to-Peer Mesh & Master Election:** The game runs completely serverless using WebRTC data channels brokered by public Nostr relays. The client with the lowest peer ID or earliest connection acts as Room Master (`isMaster === true`), orchestrating authoritative asteroid fracture/carve synchronization, periodic hazard clocks, and lobby discovery heartbeats. If the master disconnects, peers execute deterministic leader re-election without gameplay interruption.
- **Persistent Arena Coordinate Space:** The simulation takes place in a fixed cosmic reference frame:
  - Central Colossus Mega-Asteroid is stationary at `(0, 0, 0)` with nominal radius $R = 2800\text{u}$ ($scaleR = 3500\text{u}$).
  - Keplerian Orbital Belt spans $R_{\text{orbit}} \in [3300, 5500]\text{u}$ containing 90–110 procedural asteroids.
  - Ships spawn safely in orbit at `(0, 80, 3200)` with camera far clip set to $12000\text{u}$, starfield radius at $7500\text{--}8500\text{u}$, and hard sector boundary at $6500\text{u}$.
- **Volumetric MarchingCubes Density Invariant:** Asteroids are defined by discrete 3D density fields ($D \in [0, 100]$) evaluated across a cubic lattice (`mc.field`).
  - Solid terrain exists where $D > \text{mc.isolation}$ ($40.0$).
  - Navigable cavity, cavern corridors, and exterior space exist where $D \le 40.0$.
  - Density fields follow a solid core radial gradient $D = \max(0, (1.0 - (dist + noise)) \times 100)$ with `scaleR = radius / 0.80`, guaranteeing solid interiors ($D \ge 70-100$) and smooth Hermite boundary falloff ($D = 0$ on all outer bounding faces to prevent box-clipping artifacts).
- **Decoupled Pilot POV & Hull Orientation Invariant:** The starfighter employs an instant, unthrottled Pilot POV look target (`desiredQuaternion`, camera look) steered by mouse or touch, while the physical starfighter hull (`quaternion`) rotates toward `desiredQuaternion` bounded strictly by the ship's upgradeable capability limit `capabilities.maxTurnRate = 0.75 rad/s`. Forward propulsion and fixed weapon boresights align strictly with the physical hull (`ship.getForwardVector()`).
- **Dual-Gate Combat Engagement Invariant:** Fire Laser power-ups collected from meteor crater basins persist for a baseline duration (75 seconds) and are guaranteed never to expire until at least one complete dogfight engagement (`engagementsCompleted >= 1`) against an opponent starfighter has concluded.
- **Deterministic World State & Carve History Replay:** All density modifications (laser borer shafts, missile explosions, meteor impact craters) are broadcast with deterministic parameters over P2P data channels (`asteroid_carve`). Late-joining peers request and replay the full historical sequence (`applyCarveHistory`) with loopback echo suppression to maintain identical MarchingCubes meshes across all clients.

### Feature Specifications

#### Flight Subsystem
- **6DOF Flight Physics:** Newtonian starfighter dynamics with forward thrust, lateral strafe, pitch, yaw, and roll.
- **Configurable Acceleration & Momentum Shearing Flight Dynamics:**
  - Configurable Forward Acceleration: Tunable via room configuration slider (`forwardAccel` $\in [20.0, 180.0]\text{ u/s}^2$, default $180.0\text{ u/s}^2$). Continuous-thrust hyper-speed acceleration scales proportionally at $1.5 \times \text{forwardAccel}$ ($a_{\text{hyper}} \in [30.0, 270.0]\text{ u/s}^2$, default $270.0\text{ u/s}^2$).
  - Momentum Shearing Knob ($S \in [0.0, 1.0]$, default $0.1$; $0.0$ restores classic Newtonian): When the pilot activates forward thrust, velocity $\vec{v}$ is decomposed relative to the physical hull forward unit vector $\hat{f} = \text{ship.getForwardVector()}$:
    $$v_\parallel = \vec{v} \cdot \hat{f}, \quad \vec{v}_\perp = \vec{v} - v_\parallel \hat{f}$$
    1. Transverse Drift Damping: Lateral momentum decays at rate $k_{\text{shear}} = 2.5\text{ s}^{-1}$:
       $$\vec{v}_\perp \leftarrow \vec{v}_\perp \cdot \max(0, 1.0 - S \cdot k_{\text{shear}} \cdot dt)$$
       At $S = 1.0$, transverse drift dissipates rapidly (~92% per second), snapping momentum into newly faced directions within ~1.2s instead of drifting endlessly.
    2. Retrograde Opposing Velocity Cancellation: If the hull is reversed relative to travel direction ($v_\parallel < 0$), opposing momentum is actively sheared down at $k_{\text{retro}} = 2.0\text{ s}^{-1}$ in addition to forward acceleration:
       $$v_\parallel \leftarrow v_\parallel \cdot \max(0, 1.0 - S \cdot k_{\text{retro}} \cdot dt)$$
       reducing 180° complete reversal turnaround from 9.33s to under 1.5s at $S = 1.0$.
    3. Reassembly & Zero Coasting Drag Invariant: $\vec{v} \leftarrow v_\parallel \hat{f} + \vec{v}_\perp$ followed by forward thrust addition and max speed clamping. When thrust is inactive (`thrust === false`), momentum shearing is strictly bypassed, fully preserving zero-gravity space inertia, glide, and evasion drift.
- **Speed Regimes:**
  - Sustained Cruising Speed: `maxSpeed = 280.0 u/s` with configurable forward acceleration `forwardAccel` (default `180.0 u/s^2`).
  - Continuous-Thrust Hyper-Speed: Holding thrust while at or above cruising speed accelerates the starfighter at `hyperAccel = 1.5 * forwardAccel` up to `hyperSpeed = 560.0 u/s`.
  - Thrust-Release Deceleration: Releasing the thrust key decelerates the ship back to `maxSpeed` at `hyperDecelRate = 350.0 u/s^2`, smoothly preserving cruising momentum in zero gravity.
  - Emergency Braking: Decelerates the starfighter to a complete halt at `decelRate = 420.0 u/s^2` (~0.67s from full cruising speed).
- **Roll Input Smoothing:** Target roll inputs ramp smoothly at 6.0 units/s (`currentRollInput` to `targetRollInput`), eliminating abrupt snaps when pressing or releasing keyboard roll keys (`Q`/`E`) or analog triggers.
- **Rotational Capability Limits:** Pitch and yaw input rates operate at 3.2 rad/s for pilot look, while physical hull orientation tracks look direction limited by `capabilities.maxTurnRate = 0.75 rad/s`.
- **Momentum-Directed Charged Blink & Predictive Landing Hologram:** Continuous charging up to 1.0s displaces the starfighter forward by 1x to 10x hull length (28.0u to 280.0u) along its forward vector upon release. Velocity vectors are completely preserved (blink teleportation, no speed boost) with 2.0s cooldown. During warp charging, the predictive landing hologram displays a high-fidelity 12-component 5x starfighter replica (`createShipReplicaGroup`) matching exact hull geometry at the target destination with vibrating focus (spatial micro-jitter, out-of-focus scale/angular oscillation, and dynamic opacity shimmer scaling with charge ratio), 5x scaled post-blink blur animation duration (750ms), and room-synchronized translucency knob (default 80% translucency = 0.20 base opacity).
- **Ship-to-Ship Bumper Collision:** Elastic bumper deflection with relative velocity deflection and a 0.25s damage debounce to avoid multi-frame collision grinds.

#### Weapons Subsystem
- **Primary Continuous Sustained Laser Beam & Continuous Surging Oscillating Laser Energy Particle System:**
  - Twin converging high-energy laser beams emitted from wing hardpoints, tracking dynamically from ship emitters to hit point every frame with rock-solid steady continuity (zero flashing, pulsing, or tick resets while trigger is held).
  - Continuous Surging & Oscillating Laser Energy Particles (`LaserSurgeSystem`): High-energy plasma nodes and oscillating electromagnetic filaments surging forward along twin beam paths from emitter hardpoints to hit point.
    - Mathematical Formulation: Evaluates a dynamic parametric traveling wave field along the beam segment $[\vec{P}_{\text{origin}}, \vec{P}_{\text{hit}}]$ with propagation velocity $v_{\text{surge}} = 420.0\text{ u/s}$ and continuous simulation time $t$:
      $$s = (u_{\text{base}} + v_{\text{surge}} \cdot t / L) \pmod{1.0} \cdot L$$
    - Multi-Strand Harmonic Synthesis:
      1. Core Energy Soliton Packets (axial $r=0$): Pulsating energy packets modulated by longitudinal wave frequency $\sin(\omega_{\text{surge}} t - k_{\text{surge}} s)$ ($\omega_{\text{surge}} = 22.0\text{ rad/s}$, $k_{\text{surge}} = 0.08$), generating incandescent surging pulses rushing down the beam core.
      2. Counter-Phase Double-Helix Outer Filaments: Two intertwined helical strands orbiting the beam axis with angular frequency $\omega_{\text{helix}} = 16.0\text{ rad/s}$ and wavenumber $k_{\text{helix}} = 0.14$:
         $$\vec{P}_{\text{filament}} = \vec{A} + s \hat{w} + R_{\text{helix}} \sqrt{\sin(\pi u)} (\hat{u} \cos(\theta) + \hat{v} \sin(\theta))$$
         where $R_{\text{helix}} = 0.58\text{u}$ envelopes the outer glow cylinder and smoothly tapers to zero at emitter hardpoints and hit point.
    - Chromatic Palette Modulation:
      - Standard Local Laser: Blinding white-hot core solitons ($r,g,b \ge 0.90$) with vivid electric cyan (`0x00d4ff`) and azure cobalt (`0x2680ff`) double-helix filaments.
      - Crater Fire Laser: Incandescent sun-gold core solitons (`0xfff2b3`) with blazing solar orange (`0xff730d`) and vermillion crimson (`0xff2605`) filaments.
      - Remote Peer Lasers: White-hot core solitons with hot neon magenta (`0xff0d99`) and electric violet (`0xb31aff`) filaments.
    - GPU Instancing & Zero-Heap Architecture: Single-draw-call `THREE.InstancedMesh(1024)` with camera billboarding, `DynamicDrawUsage`, `frustumCulled = false`, zero runtime allocations, dirty-range `_prevActiveCount` upload skipping, and `particleDensity` scaling ('low' 0.5x, 'balanced' 1.0x, 'high' 1.5x).
  - Decoupled Frame-Rate Visual Tracking & Zero-Heap Updates: Per-frame visual transform updates (`lookAt(hitPoint)`, midpoint, scale along Z) executed via module-scoped scratch vectors at full display framerate (60–240 FPS) completely decoupled from combat/excavation pacing.
  - Persistent Material Pooling & Zero Disposal Churn: Laser core and glow materials (`localLaserCoreMat`, `localLaserGlowMat`, `fireLaserCoreMat`, `fireLaserGlowMat`, `laserSurgeSystem.material`) are shared and pooled. Firing release toggles visibility/pooling without calling `material.dispose()`, keeping WebGL shader programs permanently cached in GPU memory.
  - Range: $3500.0\text{u}$ reach with $160.0\text{ u/s}$ projectile visual velocity.
  - Energy Economy & Pacing: Max energy 100.0, consumption 20.0 energy/s (4.0 per 0.20s continuous laser tick), sustaining exactly 5.0 seconds of continuous fire. 0.5s cooldown delay, then full recharge in 4.0s at 25.0 energy/s.
  - Combat Damage & Network Sync: 2.4 damage per tick (30 DPS hull, 72 DPS shield). Dedicated `laser` P2P channel broadcasts twin emitter origins and hit point. Remote peers maintain continuous beam persistence across network packets via peer ID caching to eliminate packet-jitter flicker.
  - Continuous Spherical Asteroid Carving: Each continuous beam contact tick (every 200ms / 0.20s) directly invokes `carveAsteroid` to excavate a spherical volume at the laser hit point. Sized to carve out approximately 10% of the starfighter's volume per 200ms contact tick ($R_{\text{carve}} = R_{\text{ship}} \times \sqrt[3]{0.10} \approx 6.5\text{u}$ for $R_{\text{ship}} = 14.0\text{u}$), requiring ~2.0 seconds of continuous beam firing to excavate 100% of the ship's volume equivalent. Players must actively aim and guide the beam to sculpt and hollow out their desired cavern or tunnel geometry. Small 20 HP asteroids receive 2.0 damage per 200ms tick and shatter into 28 debris chunks on the 10th shot ($2.0 \times 10 = 20.0\text{ HP}$, 2.0s). Continuous localized contact sparks replace rapid fireball strobes during sustained drilling.
- **Crater Fire Laser Upgrade:**
  - 1.75x damage multiplier (4.2/tick vs ships, 3.5 vs small asteroids, 23.6 vs mega-asteroids).
  - 1.4x larger asteroid excavation volume ($R_{\text{fireLaser}} = R_{\text{carve}} \times \sqrt[3]{1.4} \approx 7.27\text{u}$) with fiery orange/gold beam materials and fiery spark bursts.
  - Governed by the dual-gate persistence model (75s baseline + $\ge 1$ dogfight engagement completed).
- **Secondary Dual-Mode Missile Arsenal:**
  - Guided Mode: Line-of-sight tracking within crosshair cone for 3.0 seconds achieves target lock with `StandardPursuitGuidance` (max turn rate 3.2 rad/s, base acceleration 50.0 u/s²).
  - Dumb-Fire Mode: Unlocked firing launches missiles directly forward along hull heading with proximity detonation against enemy starfighters.
  - Ventral Underbelly Launch: Missiles fire from a ventral hardpoint displaced downward by 3.0u along the ship's local down vector (`ship.getDownVector()`) and 2.5u forward along the nose, ensuring billowing GPU smoke plumes remain completely beneath the cockpit canopy FOV.
  - Velocity Inheritance & Separation Clamping: Missiles inherit the starfighter's 3D velocity vector. Dynamic separation clamping enforces $v_{\text{missile}} \ge v_{\text{ship}} + 85.0\text{ u/s}$ and $v_{\text{max}} \ge v_{\text{ship}} + 210.0\text{ u/s}$ across cruising ($280\text{ u/s}$) and hyper-speed ($560\text{ u/s}$) regimes, preventing ships from catching up to their own ordnance.
  - Detonations: Impacts blast large craters ($r=45\text{u}, d=35\text{u}$) with multi-stage GPU instanced explosions (Stage 1 core, Stage 2 planar shockwave ring & puffs, Stage 3 radial sparks & outer smoke).

#### Asteroids & Volumetric Voxels Subsystem
- **Volumetric MarchingCubes Fields:** Replaces polygonal meshes with dynamic density fields using `ISOSURFACE_SCALE = 0.80` and `isolation = 40.0`.
- **Quality Presets:** Configurable 3-tier grid scaling: `'low'` ($32^3$), `'medium'` ($48^3$), `'high'` ($64^3$, default).
- **Volumetric Ray-Marching Hitscan:** `checkRayCollision` marches through `mc.field` with binary search sub-voxel bisection refinement to pinpoint exact isosurface crossings up to 3500u.
- **Sphere-Shaped Continuous Laser Carving Spec:** Localized spherical excavation centered at the laser contact point (`localHit`) on the asteroid surface. Sized by room configuration parameter `carveRadius` (default $6.5\text{u}$, matching ~10% ship volume where $R_{\text{ship}} = 14.0\text{u}$ via $R_{\text{carve}} = 14.0 \times \sqrt[3]{0.10} \approx 6.5\text{u}$; Crater Fire Laser yield $\approx 7.27\text{u}$). Employs cubic Hermite smoothstep radial falloff ($\text{factor} = u^2(3 - 2u)$ where $u = 1 - \text{dist}/r$), localized AABB grid bounds, nearest-voxel fallback, and clean normal updates via `updateNormalCache`. Eliminates legacy capsule clamps ($r \ge 180\text{u}, d \ge 260\text{u}$), requiring the player to skillfully guide and aim the beam to sculpt custom tunnels, trenches, and cavern geometries.
- **Continuous Swept Multi-Point Density Field (CCD):** Velocity-adaptive sub-stepping ($N \le 16$) evaluating a 6-point hull envelope (center, nose, tail, wings, belly) along swept paths across 280–560 u/s. Collisions push ships outward along the local density gradient $\nabla D$ with `safeMargin = shipRadius + 0.6`, while granting natural clearance inside excavated cavern corridors where $D \le 40.0$.
- **Geological Strata & Shaders:** Dynamic vertex colors (`enableColors = true`) in `mc.palette` with altitude/crater darkening; dirty-subvolume AABB `updateNormalCache` unit-normalized gradients; custom triplanar shader `applyTriplanarRockShader` supporting `'low'`, `'balanced'` (hardware screen-space `dFdx`/`dFdy` derivative normal perturbation), and `'high'`.

#### Rendering & Performance Subsystem
- **Uncapped High-Framerate Engine (200+ FPS):** Default `maxFps = 0` (Unlimited) across engine, lobby, and URL params; selectable options: `0` (Unlimited), `240` (Ultra), `120` (Pro), `90` (High), `60` (Eco).

- **Belt Asteroid Culling & Right-Sized VBOs:** `THREE.FrontSide` backface culling, bounding sphere frustum culling, and 6,000-poly MarchingCubes VBO allocation saving ~275 MB VRAM.
- **GPU InstancedMesh Quad Billboarding:** Unified single-draw-call particles with sub-frame distance interpolation, dirty-range `_prevActiveCount` upload skipping, and configurable `particleDensity` ('low' 0.5x, 'balanced' 1.0x, 'high' 1.5x).
- **Invariant PointLight Define Stability & Zero-Hitch Lighting:** Permanent `visible = true` invariant across all dynamic point lights (`combatFlashLight`, `meteorLight`). Rather than toggling `visible` (which alters `#define NUM_POINT_LIGHTS` and triggers full Three.js shader program recompilation across all illuminated scene objects on the first shot), lights modulate `.intensity = 0.0` when idle. Shaders compile once with a fixed light count and never recompile.
- **Upfront Shader & Weapon Asset Pre-Warming (`prewarmShaders`):** Compiles all scene materials, procedural triplanar rock shaders, ship cockpit canopy, laser beams, fire laser variants, and particle quads during initial engine bootstrap before the first gameplay frame.
- **Static Bounding Sphere Reduction Bypass:** Invariant pre-allocated outer bounding spheres on MarchingCubes asteroid geometries ($R = 2800\text{u}$ on mega, belt radius on orbital rocks) bypass redundant 150k vertex CPU buffer scans during real-time combat fracture ticks.
- **High-Resolution Micro-Benchmarking & Performance Telemetry:** Structured micro-benchmarking using `performance.now()` across weapon firing, volumetric raycasting, asteroid fracture, audio synthesis, and frame rendering with structured `[PERF:]` tags and a 5ms warning threshold (`[PERF:WARN]`).
- **Distant Star-Glow Beacon:** Additive billboard with radial soft-glow DataTexture scaling smoothly from 100u to 6000u+ for long-range target acquisition.

### Superseded & Deprecated Architectural Decisions

- **Flat-Core "Bigger Than Ship" Capsule Tunnel Borer ($r \ge 180\text{u}, d \ge 260\text{u}$):** Superseded by continuous spherical laser carving at contact point ($R_{\text{carve}} \approx 6.5\text{u}$, ~10% ship volume per 200ms tick) with room configuration parameter `carveRadius`.
- **17-Stage Continuous Laser Fracture Delay:** Superseded by direct 200ms continuous beam carving cadence where every 200ms tick removes a spherical volume and small asteroids take 2.0 damage per 200ms tick (destroyed in 10 shots / 2.0s).
- **Battle Royale Mode & Shrinking Zone (`blackhole.js`):** Removed in favor of persistent planetary exploration, Keplerian orbital belt, and stationary central mega-asteroid.
- **Discrete Pulsed Laser Fire & Legacy Damage Tunings:** Superseded by continuous sustained twin laser beam.
- **Legacy Low-Speed Cruising (140 u/s) & Evasive Boost:** Superseded by doubled cruising speed (280 u/s), continuous-thrust hyper-speed acceleration (560 u/s), and momentum-directed charged blink.
- **Manual Service Worker Version Bumping:** Superseded by automated build-time cache ID injection (`__BUILD_ID__`).

## 7. Financial & Safety Guardrails

- **Cost Management & Serverless Architecture:**
  - **Zero Central Hosting Cost:** Hosted 100% statically on GitHub Pages with zero cloud compute, database, or server maintenance bills ($0.00/month).
  - **Decentralized Data Transport:** Direct peer-to-peer WebRTC data channels carry all per-frame multiplayer physics, orientation, and combat packets, incurring zero central bandwidth expenses.
- **Safety & Decentralized Relay Rate-Limit Guardrails:**
  - **Public Nostr Relay Rate-Limit Protection:** Client signaling utilizes a relaxed 6-second heartbeat cadence (`HEARTBEAT_INTERVAL_MS = 6000`, `ROOM_TTL_MS = 18000`) across `relay.primal.net`, `nos.lol`, and `nostr.mom`. This prevents HTTP 429 rate-limiting bans on public relays and ensures continuous lobby discovery.
  - **Multi-Relay Fallback:** If any single Nostr relay experiences downtime or rate limits, remaining relays maintain lobby discovery and WebRTC connection negotiation.
  - **Packet Size Guardrails:** Peer-to-peer data packets are strictly capped (<64 KB per payload) with binary or compact JSON serialization to prevent browser memory leaks or WebGL frame stalls.
- **Security & Secrets Management:**
  - **Zero Repository Secrets:** No API keys, credentials, or private keys are stored in the codebase or repository.
  - **Ephemeral Nostr Keys:** Nostr client keypairs are generated ephemerally in browser memory per session and are never written to disk or transmitted to external servers.
  - **Hidden Production Sourcemaps:** Sourcemaps are configured as `hidden` (`sourcemap: 'hidden'` in `vite.config.js`) to enable error stack resolution in diagnostic logs without exposing proprietary source code files publicly.
